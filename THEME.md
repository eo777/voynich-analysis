# Shared presentation contract

The author edits article Markdown and `media.yml`. The designer edits `theme/`. Keep these responsibilities separate.

## Entry points

- `theme/assets/site.css`: page typography, spacing, grid, gallery, viewer, mobile and print behavior. CSS custom properties at `:root` are the design tokens, including native-chart palettes.
- `theme/templates/base.njk`: common page shell, navigation, stylesheet/script references, image dialog.
- `article.njk`, `index.njk`, `gallery-page.njk`: page layouts.
- `figure.njk`, `chart.njk`, `gallery.njk`: reusable media components.
- `theme/assets/site.js`: shared interactive behavior.
- `theme/charts/heatmap.js`: native SVG chart layout and rendering. Its colors and font come from the shared CSS tokens.
- `theme/charts/continuous-method.js`: manuscript-image overlays, example-pair controls, and a continuous-kernel explanation. Its layout uses the shared `.method-*` CSS rules. Article data supplies the registered polygons and precomputed illustrative fields; this component does not change study results.

Neither HTML nor CSS is embedded into individual article source files. The check command also rejects inline `<style>` blocks and `style` attributes in built pages. Native SVG geometry is generated by the shared chart implementation, not article-specific scripts. Downloaded scientific PNG/SVG figures retain their scientific formatting; redesign the shared viewer without altering their plotted values.

## Template data

All templates receive `site`, `url(relativeSitePath)`, and `asset(relativeSourcePath)`. `asset` adds a content fingerprint. Avoid hard-coded root paths: this is a GitHub project site under `/voynich-analysis/`.

Article templates receive `article` with `title`, `summary`, `date`, `tags`, `status`, `slug`, and `path`; rendered prose is `content`. Media definitions are resolved and validated by the builder before components receive them. Nunjucks autoescapes labels and captions.

## Behavioral hooks to preserve

- `[data-gallery]`, `[role=tab]`, `[role=tabpanel]`, and `[data-gallery-count]` provide keyboard gallery navigation. Preserve tab IDs and `aria-controls` / `aria-labelledby` relationships.
- `[data-image-open]` and `data-title` open the shared image dialog. The anchor remains a working image link without JavaScript.
- `[data-chart-module]`, `[data-chart-source]`, and `[data-chart-preset]` load registered chart modules into `.chart-mount`. Hidden gallery charts mount only after selection.
- The `.image-viewer` dialog retains `#viewer-title`, `[data-viewer-size]`, `[data-viewer-close]`, and `.viewer-image`.
- `.skip-link`, visible focus states, contrast, reduced-motion preferences, and small-screen overflow should remain usable.
- `[data-copy-link]` remains an ordinary anchor with a real fragment URL; JavaScript enhances it with clipboard copying. Keep the named heading, figure, chart, and gallery IDs stable. Gallery fragments reveal their panel before scrolling. `[data-chart-link]` includes the current chart selections in its URL.

## Add a chart type

1. Put a module in `theme/charts/` exporting `async function mount(element, { source, preset })`.
2. Register its path in `site.config.mjs` under `charts`.
3. Define an article chart with that `type`, a relative data path, a static fallback image, title, and caption.

Modules should render only within the supplied element and support multiple instances per page. Use no global element IDs. Fetch only the supplied static data; no service credentials belong in browser code. Fail visibly while retaining the static fallback and JSON links.

## Verify a redesign

Run `npm test` and `npm run check`, then `npm run serve`. Check the home page, an article, its separate gallery, a native chart, image expansion, keyboard gallery navigation, a narrow viewport, and print layout. The deployment workflow performs the build checks on every push.
